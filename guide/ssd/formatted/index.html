⚡ SSD (SATA and NVMe) · 🧹 Accidentally formatted

Recover Data from a Formatted SSD

Formatting wipes the SSD's file list (the index of what is stored where). Formatting an SSD, especially a full format or a reinstall of the operating system, commonly triggers TRIM (a feature that tells the SSD to wipe unused space), which erases the old data. Quick formats on internal SSDs are usually not recoverable. External or older setups that skip TRIM may still hold data.

2/5 · Low risk
Success odds: Low

Reinstalling Windows or saving new files on the SSD speeds up permanent loss, so careless steps can end any chance of recovery.

✋ Stop! Don't do this first

  • Do not copy new files to the SSD or reinstall the operating system on it. That overwrites old data.
  • Do not install recovery software on the formatted SSD.
  • Do not format it again, even if Windows or macOS offers.

Your steps

0 of 7 done
  1. Show me how
    1. Windows: Start > Power > Shut down. Mac: Apple menu > Shut Down.
    2. If it will not shut down, hold the power button about 10 seconds.
    3. Leave it off until you are ready for the next step.
  2. Show me how
    1. Plug the SSD into a second computer with a USB-to-SATA cable, an M.2 USB enclosure or a drive dock.
    2. No second computer? Start yours from a Live USB (a Linux USB stick that runs without using your SSD). The guide below shows how.
    3. If a window says the drive needs formatting, click Cancel. Never click Format.
    4. In Disk Management (Windows) or Disk Utility (Mac) check that the SSD appears. Do not change anything there. Open it: Windows: right-click the Start button and choose Disk Management. If a window pops up asking to initialize the disk, click Cancel. Mac: press Cmd+Space, type Disk Utility and press Enter, then click View > Show All Devices.

  3. Show me how
    1. Ask yourself: did you reinstall Windows or macOS, or choose Erase in Disk Utility, or untick Quick Format in Windows? Those are full wipes and almost always final.
    2. If you only did a quick format on an external or older SSD, there is a real chance.
    3. Write down what happened. A recovery lab will ask.
    4. Either way, carry on with the copy in the next step.
  4. Show me how
    1. You need a second drive with free space at least as big as the SSD. Plug it in and note its name.
    2. Windows: ddrescue runs from Linux, so follow the Live USB guide to start your PC from a Linux USB stick (a stick that starts a temporary Linux without touching your drive). When the Linux desktop appears, press Ctrl+Alt+T to open the Terminal and type sudo apt install gddrescue (the imaging guide explains what to do if it is not found). Mac: press Cmd+Space, type Terminal, press Enter, then type brew install ddrescue (needs Homebrew from brew.sh).
    3. Find the SSD's name. Linux: type lsblk -o NAME,SIZE,MODEL and match it by size (it looks like sdb, which you type as /dev/sdb). An NVMe SSD shows as nvme0n1. Mac: type diskutil list (it looks like /dev/disk4). Pick by size, never guess. Then open the destination drive in the Files app (Mac: Finder) so it is ready, but do not open the SSD.
    4. Mac only: type diskutil unmountDisk /dev/disk4 (use your number) so the Mac lets go of it. Do not click Initialize or Erase if a window pops up.
    5. Type sudo ddrescue -n /dev/sdX /media/ubuntu/DEST/ssd.img /media/ubuntu/DEST/ssd.map. Replace sdX with the SSD's name (an NVMe SSD shows as nvme0n1 instead, so you would type /dev/nvme0n1) and DEST with your destination drive's name (on Linux Mint the folder is /media/mint/ instead). On a Mac, use /dev/diskN as the first path and /Volumes/DEST/ for the other two. The first path is the SSD (the source), the second is where the copy goes. Swapping them erases the SSD.
    6. Wait until it says it is finished. Keep the .map file: it lets you stop and resume. Work only on an image file from now on.

  5. Show me how
    1. Open TestDisk (a free tool that finds lost partitions, meaning the sections of a drive, and deleted files). Windows: download it from cgsecurity.org, right-click the zip, choose Extract All, then right-click testdisk_win.exe and choose Run as administrator. Linux live USB: in the Terminal (Ctrl+Alt+T) type sudo apt install testdisk, then sudo testdisk. Mac: in Terminal type brew install testdisk, then sudo testdisk.
    2. If you made an image, start TestDisk on the image instead: type sudo testdisk /media/ubuntu/DEST/ssd.img (use your own folder and file name). Otherwise it lists your drives.
    3. Choose Create (log file), pick the drive or image with the arrow keys, choose Proceed, then accept the partition table type it suggests, usually Intel/PC or EFI GPT, and press Enter.
    4. Choose Analyse, then Quick Search. If a partition shows with your folders, press p to list its files, then c to copy them to a different drive.
    5. Use the arrow keys and Enter to move around and q to go back. TestDisk only changes anything if you choose Write, so do not choose it.

  6. Show me how
    1. Open PhotoRec (a free tool that searches for file contents instead of file names; it comes with TestDisk). Windows: in the unzipped TestDisk folder, right-click qphotorec_win.exe and choose Run as administrator (this version has buttons). Linux live USB: type sudo apt install testdisk if you have not yet, then sudo photorec /media/ubuntu/DEST/ssd.img to search your image. Mac: brew install testdisk, then sudo photorec. The text version uses the arrow keys and Enter.
    2. Pick the drive or image from the list (text version: then choose Proceed), then the partition, or the Whole disk line if unsure. When asked for the file system, pick Other (the window version calls it FAT/NTFS/HFS+/ReiserFS/...) unless it was a Linux drive (ext2/ext3/ext4). Choose Free for deleted files, or Whole for formatted, RAW or damaged drives.
    3. Click File Formats and untick types you do not need to save time. Some names differ from the file endings: keep jpg and png for photos, mov for MP4 and MOV videos, pdf, and zip for DOCX and XLSX. Text version: choose File Opt before Search, press s to untick everything, tick types with the Space bar, then press q to go back. Skipping this is also fine.
    4. Choose where to save results: a folder on a different drive, never the SSD itself. Window version: click Browse. Text version: after Search it shows a list of folders; move to /media/ubuntu/DEST with the arrow keys and Enter, then press C.
    5. Window version: click Search. It can take hours. Leave the computer on until it says it has finished.

    Guide: How to use PhotoRec to recover photos and files

  7. Show me how
    1. Open the folder PhotoRec or TestDisk saved into. PhotoRec makes folders called recup_dir.1, recup_dir.2 and so on with numbered file names.
    2. Windows: click Sort by > Type in File Explorer. Mac: click View > as List, then click the Kind column.
    3. Double-click a few files of each type. A photo that shows, a document that opens or a video that plays means it worked.
    4. Files that will not open, or look blank or all gray, are damaged or already erased. Open a few more before deciding.
Mission complete! 🎉 Check your recovered files open properly, then back them up in two places.

Questions people ask

Will a quick format on an SSD wipe my files?

Often yes. The format itself keeps data, but TRIM usually follows and erases it. Odds are better on external SSDs or older systems without TRIM.

Can a professional get trimmed data back?

Usually not. Once TRIM has run, the SSD reports that space as blank. A lab mostly helps when the SSD itself has failed.
