How to make an image (exact copy) of a drive

An image is an exact copy of the whole drive saved as a file. You make it first and then do all recovery work on the copy, so the original drive is read as little as possible. This matters most when a drive is failing, because every extra scan can make it worse.

Time needed: A few hours to more than a day for large or failing drives

You'll need

  • A computer booted from a Linux live USB (see the live USB guide)
  • The problem drive (the source), connected but not written to
  • A second drive (the destination) with more free space than the source's full size and that holds nothing you need. It should be formatted as NTFS, exFAT or ext4, because the older FAT32 format cannot hold files larger than 4 GB
  • Internet access in the live session, to install ddrescue

Why image first

Reading a damaged drive over and over wears it out and can lose data. An image lets you read the damaged drive once or twice, then try recovery tools as many times as you like on the copy. If a tool goes wrong, your copy is still there to redo.

Step 1: Install ddrescue

ddrescue is a free tool made for copying damaged drives. It skips unreadable spots first and comes back to them later, which is gentler than a normal copy. Open the Terminal app (press Ctrl+Alt+T) in the live session.

  1. Connect to the internet from the top-right corner menu.
  2. Type: sudo apt update and press Enter.
  3. Type: sudo apt install gddrescue and press Enter. Type y if asked to continue. (The package is called gddrescue; the command it installs is ddrescue.)
  4. If you see 'Unable to locate package', type: sudo add-apt-repository universe then sudo apt update and try the install again. (Universe is an extra software source that Ubuntu may have switched off.)

Step 2: Identify your drives

You must know which drive is the source and which is the destination. Linux names drives like /dev/sda, /dev/sdb and so on. The letter at the end is the part you will replace where this guide says sdX.

  1. In the Terminal, type: lsblk -o NAME,SIZE,MODEL and press Enter.
  2. Look at the list. Whole drives show as sda, sdb, sdc. NVMe SSDs show as nvme0n1, and SD cards in a built-in slot as mmcblk0; use that whole name in place of sdX. The indented lines below them (such as sda1 or nvme0n1p1) are parts of that drive.
  3. Match drives using SIZE and MODEL. For example, a 500G drive with model WDC WD5000 is your old laptop drive, and a 2T drive with a different model is your new backup drive.
  4. Ignore the live USB stick itself. It is the small drive, often 8G to 32G.
  5. Write down the letter for the source (for example sdb) and the destination (for example sdc). Unplug other drives if the list is confusing.

⚠️ Careful: If you are not completely sure which drive is which, stop and check again. Mixing them up can erase your data.

Step 3: Make the destination drive available

ddrescue saves the image as a file on the destination drive, so that drive must be opened first, like opening a folder.

  1. Open the Files app from the dock on the left.
  2. Click the destination drive in the left sidebar. This mounts it, which means the system makes it readable and writable.
  3. Check that it opens and shows free space. Its name is the folder name used in the path, such as /media/ubuntu/DEST. In Linux Mint it is /media/mint/DEST. To see the exact name, type: ls /media/ubuntu (or ls /media/mint) and press Enter.
  4. Do not click or open the source drive. If it opened by itself, click the eject arrow next to it in the sidebar. Never choose Format there.

Step 4: Copy the drive (first pass)

This first pass copies all the easy-to-read data quickly and skips troublesome spots (that is what -n means). The map file records what has been copied so far.

  1. In the Terminal, type the command below, replacing sdX with the source drive letter and DEST with your destination's name: sudo ddrescue -n /dev/sdX /media/ubuntu/DEST/drive.img /media/ubuntu/DEST/drive.map
  2. Press Enter and type the live session password if asked (it is often blank; just press Enter).
  3. Watch the numbers. 'rescued' goes up as data is copied, and 'bad areas' shows spots that could not be read.
  4. Wait until the command finishes and you see the prompt again.

⚠️ Careful: The order matters: first the source drive (/dev/sdX), then the image file on the destination. Swapping them can overwrite your original data. Never put the problem drive's path where the image file path goes, and never save the image on the problem drive.

Step 5: Second pass for the hard spots

Now ddrescue goes back and retries the areas it skipped, up to three times (that is what -r3 means). Use the exact same image and map file so it continues where it left off. Skip this pass if the drive clicks, grinds or keeps disconnecting.

  1. Type: sudo ddrescue -r3 /dev/sdX /media/ubuntu/DEST/drive.img /media/ubuntu/DEST/drive.map
  2. Press Enter and wait. If the drive starts clicking, grinding or gets very hot, press Ctrl+C to stop, power it off and see a professional instead of trying again.
  3. When it finishes, note the 'rescued' figure. Even if a small part could not be read, the rest of your files are usually still fine.

⚠️ Careful: The order matters here too: first the source drive (/dev/sdX), then the image file, then the map file. Swapping them can overwrite your original data.

Stopping and resuming

The map file (drive.map) remembers progress. You can press Ctrl+C at any time, shut down, and later run the same command again to continue. Keep the image and map files together, and do not delete or rename them in between.

How long will it take?

A healthy 1 TB drive takes a few hours. A failing or slow drive can take a day or more, and the speed may drop sharply on damaged parts. Plug in the power and make sure the computer will not go to sleep: in Settings, turn off screen blanking and auto suspend.

Other options

HDDSuperClone is another Linux tool for failing hard drives. It has more advanced controls and is worth a look if ddrescue keeps stalling, but it is harder for beginners. ddrescue is the right place to start.

Questions people ask

Why does the destination drive have to be larger?

The image is the size of the whole source drive, including empty space. A 500 GB source needs more than 500 GB free on the destination.

Does imaging change the original drive?

No, as long as the source is the first drive in the command and nothing is written to it. ddrescue only reads from it.

What do I do with the image afterwards?

Run recovery tools such as TestDisk or PhotoRec on the image file instead of the real drive, then copy the recovered files to a third location.
